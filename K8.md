Kubernetes Notes – Pods, Deployments, StatefulSets & Storage

1. Pod
Definition
A Pod is the smallest deployable unit in Kubernetes.
A Pod runs one or more containers.
Examples
	• Nginx
	• NodeJS
	• MySQL
	• PostgreSQL
Architecture
Pod
 └── Container

Example
Pod
 └── Nginx Container


2. Service
Why Service?
Pods are temporary.
When a Pod dies, Kubernetes creates another Pod.
Old Pod
Pod Name : nginx-abc123
IP       : 10.0.0.5
New Pod
Pod Name : nginx-xyz789
IP       : 10.0.0.8
Pod name and IP change.
Instead of connecting directly to Pods, clients connect to a Service.
Architecture
Client
   │
Service (Stable IP & DNS)
   │
 ├── Pod-1
 ├── Pod-2
 └── Pod-3

Service Responsibilities
	• Stable IP
	• Stable DNS
	• Load balances requests
	• Automatically updates when Pods change

3. ReplicaSet
Purpose
ReplicaSet maintains the desired number of Pods.
Example
replicas: 3
ReplicaSet ensures
Pod-1
Pod-2
Pod-3
If Pod-2 crashes
ReplicaSet → Creates New Pod

Responsibility
Only one responsibility:
	Maintain the required number of Pods.

4. Deployment
Purpose
Deployment manages ReplicaSets.
Architecture
Deployment → ReplicaSet → Pods

Features
	• Rolling Updates
	• Rollback
	• Scaling
	• Self Healing
Deployment does NOT directly create Pods.
ReplicaSet creates Pods.
Deployment manages ReplicaSets.

Rolling Update
Before Update
Deployment
      │
ReplicaSet-v1
      │
Pod(v1)
Pod(v1)
Pod(v1)

Change Image
image: nginx:v2
Deployment creates a new ReplicaSet
Deployment
      │
      ├── ReplicaSet-v1
      └── ReplicaSet-v2

Rolling Update
ReplicaSet-v2 → Creates Pod(v2)

ReplicaSet-v1 → Deletes Pod(v1)

Repeat until all Pods become v2
Final
Deployment → ReplicaSet-v2 → Pods(v2)


Deployment vs ReplicaSet
ReplicaSet
	• Maintains desired Pods.
Deployment
	• Manages ReplicaSets.
	• Handles Updates.
	• Handles Rollbacks.
	• Handles Scaling.
Easy Memory
Deployment = Manager
ReplicaSet = Worker

5. Stateless Applications
Definition
Stateless applications do NOT store important data inside the Pod.
Examples
	• Nginx
	• Apache
	• NodeJS
	• Spring Boot
	• Python Flask
	• React
If Pod dies
Old Pod → New Pod

No important data is lost.
Kubernetes Object
Deployment

6. Stateful Applications
Definition
Stateful applications store important data.
Examples
	• MySQL
	• PostgreSQL
	• MongoDB
	• Kafka
	• Redis
These applications require
	• Persistent Storage
	• Stable Pod Identity
	• Stable Network Identity
Kubernetes Object
StatefulSet

7. StatefulSet
Why StatefulSet?
Deployment creates Pods with random names.
Example
mysql-abc123
mysql-xyz456
StatefulSet creates permanent names
mysql-0
mysql-1
mysql-2
If mysql-1 crashes
Old Pod : mysql-1
↓

New Pod : mysql-1
Identity remains the same.

Client

 Service

Headless Service
mysql-0.mysql

9. EBS (Elastic Block Store)
Think
	One Application Instance → One Dedicated Disk
Architecture
Pod → PVC → PV → EBS

If Pod crashes
Pod ❌
PVC ✅
PV ✅
EBS ✅
ReplicaSet creates a new Pod
New Pod → Same PVC → Same PV → Same EBS

No data is lost.
Can Deployment use EBS?
YES.
Example
Deployment (replicas=1)
        ↓
Pod → PVC → PV → EBS

Real Examples
	• Jenkins
	• SonarQube
	• Internal MySQL
	• Internal PostgreSQL

10. Can one EBS be shared?
No.
Wrong
Pod-1
Pod-2
Pod-3
   │
 One EBS ❌
Reason
EBS (ReadWriteOnce)
	• Attached to one node at a time.
	• Normally used by one Pod.

Beginner Memory Rule
Deployment + 1 Replica + 1 EBS = Perfectly Fine

11. StatefulSet Storage
Every Pod gets its own EBS.
mysql-0 → PVC-0 → PV-0 → EBS-0

mysql-1 → PVC-1 → PV-1 → EBS-1

mysql-2 → PVC-2 → PV-2 → EBS-2

Each Pod owns one dedicated disk.

12. MySQL Cluster
Application sends
INSERT / UPDATE / DELETE
        │
        ▼
Primary (mysql-0)
        │
Writes to EBS-0
        │
MySQL Replication
        │
        ├── mysql-1 → Writes to EBS-1
        └── mysql-2 → Writes to EBS-2

Important
	• Kubernetes does NOT replicate data.
	• EBS does NOT replicate data.
	• MySQL replicates data over the network.

16. Real World

Interview Summary
Object	Purpose	Used For
Pod	Runs Containers	All Applications
Service	Stable IP & DNS	Mostly Stateless Apps
ReplicaSet	Maintains Desired Pods	Managed by Deployment
Deployment	Updates, Scaling, Rollback	Stateless Applications
Headless Service	Stable DNS	Stateful Applications
StatefulSet	Stable Identity & Storage	Databases

Final Memory Rules
	1. Pod = Runs application.
	2. Service = Stable IP + DNS.
	3. ReplicaSet = Maintains desired Pods.
	4. Deployment = Manages ReplicaSets.
	5. Headless Service = Stable DNS for Stateful Pods.
	6. StatefulSet = Stable Pod name + Stable Storage.
	7. EBS = One Pod gets one dedicated disk.
	8. EFS = Many Pods share the same files.
	9. Deployment + 1 Replica + 1 EBS = Common and valid.
	10. StatefulSet + Multiple Pods = Each Pod gets its own EBS.
	11. Databases never share one EBS volume.
	12. MySQL replication happens over the network, not through EBS.
